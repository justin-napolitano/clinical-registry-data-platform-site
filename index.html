End-to-end flow

How a registry becomes usable data.

The pipeline is intentionally metadata managed. Raw data is preserved first; interpretation happens through versioned mapping and review artifacts.

01

Source Intake

Collect raw files, file hashes, modified timestamps, source paths, and inferred schema signatures.

02

Bronze Preserve

Land raw values into schema-version grouped bronze tables and quarantine unmapped structures without losing the run.

03

Silver Normalize

Apply approved source-to-canonical mappings, casts, aliases, nullable policy, and semantic grouping.

04

Gold Publish

Publish governed flat contracts for analytics, Power BI coverage, filters, and business logic review.

05

Review + Promote

Export decisions into patch artifacts, validate through the control plane, and promote by pull request.

Metadata collected

The platform captures the evidence behind every transform.

Bronze

Raw provenance and schema evidence

  • Registry id, source file path, file hash, source modified timestamp
  • Ingestion run id, ingested timestamp, source schema version
  • Structure bucket, bronze table, column ordinal, inferred type
  • Row counts, load status, quarantine reason, validation errors
Silver

Canonical mapping and normalization evidence

  • Source schema version, bronze table, source column, target silver column
  • Mapping status, match rule, confidence score, mapping evidence
  • Target type, nullable policy, semantic group, transform rule
  • Approved by, effective version range, lineage key, validation status
Gold

Publication contract and analytics evidence

  • Published column list, source silver table, target gold table
  • Business rule notes, filters, inclusion status, review status
  • Power BI coverage, missing fields, candidate publication gaps
  • Versioned contract artifacts for governed promotion
